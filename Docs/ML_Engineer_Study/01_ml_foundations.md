## 1. Типы машинного обучения

### Supervised learning
Есть входные данные **X** и известный правильный ответ **y**. Модель учится приближать отображение:

`X -> y`

Примеры:
- классификация изображения;
- регрессия;
- object detection, если у нас есть размеченные изображения.

В этом проекте обучение YOLO относится к supervised learning: на обучающих изображениях заранее размечено, где находится целевой объект.

### Unsupervised learning
Есть данные, но нет заранее заданного правильного ответа. Модель ищет структуру сама.

Примеры:
- кластеризация;
- снижение размерности;
- поиск необычных объектов.

В основной архитектуре GFS-X это сейчас не центральный подход.

### Reinforcement Learning
Агент взаимодействует со средой:

`observation -> action -> reward -> новое состояние`

Задача — научиться выбирать действия, максимизирующие ожидаемую суммарную награду.

В GFS-X этот подход используется для управления поведением робота через Unity ML-Agents.

---

## 2. Train / Validation / Test

### Train
Данные, на которых меняются параметры модели.

### Validation
Данные, на которых мы выбираем гиперпараметры, checkpoint и сравниваем варианты.

### Test
Данные, которые не должны использоваться при выборе модели. Нужны для финальной независимой оценки.

Главная идея: если оценивать модель на тех же данных, на которых она училась, можно получить слишком оптимистичную оценку.

---

## 3. Overfitting и Underfitting

### Underfitting
Модель недостаточно хорошо описывает даже обучающие данные.

Признак:
- плохой результат и на train, и на validation.

### Overfitting
Модель хорошо запоминает train, но плохо работает на новых данных.

Признак:
- train становится лучше;
- validation перестает улучшаться или ухудшается.

Для робота overfitting может проявляться особенно неприятно: модель отлично работает в знакомой сцене Unity, но нестабильно — в другой сцене или на реальном роботе.

---

## 4. Loss и optimization

**Loss function** — число, которое показывает, насколько плох текущий результат модели.

Во время обучения оптимизатор меняет параметры модели так, чтобы уменьшать loss.

Важно:
- loss нужен для обучения;
- конечная метрика качества может быть другой.

Например, YOLO оптимизируется по набору внутренних loss-компонентов, а итоговое качество мы можем оценивать через precision/recall/mAP.

---

## 5. Метрика должна соответствовать задаче

Нельзя выбирать метрику только потому, что она привычная.

Для real-time робота могут одновременно быть важны:
- качество детекции;
- число пропусков объекта;
- false positives;
- latency;
- FPS;
- стабильность поведения;
- вероятность успешного захвата мяча.

То есть модель с большим mAP не обязательно даст лучшего робота, если она работает слишком медленно.

---

## 6. Domain shift

**Domain shift** — обучающие и реальные данные отличаются.

В GFS-X это особенно важно:

- Unity-картинка != изображение веб-камеры;
- виртуальные расстояния != шумные реальные сенсоры;
- идеальная динамика моторов != реальные двигатели;
- отсутствующая задержка != ROS + камера + inference + моторы.

Это одна из центральных причин проблем sim-to-real.
